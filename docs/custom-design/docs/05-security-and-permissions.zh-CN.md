# 05. 安全与权限策略

## 1. 原则

编程 Agent 必须拥有完成正常任务所需的读、写、编辑、执行和测试能力，不能因过度限制而每一步询问用户。安全应通过角色分工、作用域和危险操作门禁实现，而不是一刀切禁用工具。

## 2. 角色权限

- Planner / Orchestrator：规划与委派，可保持较窄工具集。
- Worker：拥有当前项目内完成任务所需工具。
- Guardian / Reviewer：默认只读，不直接修改代码。
- Test Executor：可执行测试和创建必要测试文件，但仍受项目范围限制。

## 3. 最高风险门禁

下列操作必须展示准确命令、影响范围和回退方式，并等待人工明确确认，或由人工执行：

- 递归或批量删除
- 磁盘分区、格式化、文件系统、RAID、LVM 操作
- 生产服务、生产数据库和真实用户数据修改
- 大范围权限、所有权或安全策略修改
- 防火墙、路由、远程访问和管理口变更
- 安装脚本中的不透明远程执行
- 可能越出当前仓库、Workspace 或挂载范围的命令
- 不可逆迁移或无法验证回退的操作

## 4. 普通工程操作

在当前仓库和明确范围内，以下操作可按计划自动执行：

- 读取与搜索文件
- 小范围编辑
- 创建测试与文档
- 运行项目已有测试、lint、build
- 安装已经审查并由计划明确需要的项目依赖

## 5. 审计

危险操作请求、用户确认、实际命令、返回状态和后续验证必须写入长期日志。
